# 近期参考文献整理

> 说明：以下文献重点覆盖多源/混合检索、RAG、深度检索流程、任务规划、多智能体、长短期记忆与上下文压缩等方向，尽量以 2023–2026 年的较新文献为主，便于用于本科论文中的“相关技术与研究现状”“系统设计与实现”“测试与分析”等部分。

6. **LightRAG: Simple and Fast Retrieval-Augmented Generation**（2024）  
7. **RAGChecker: A Fine-grained Framework for Diagnosing Retrieval-Augmented Generation**（2024）  
8. **Adaptive-RAG: Learning to Adapt Retrieval-Augmented Large Language Models through Question Complexity**（2024）  
9. **RankRAG: Unifying Context Ranking with Retrieval-Augmented Generation in LLMs**（2024）  
10. **REPLUG: Retrieval-Augmented Black-Box Language Models**（2023）  
11. **Retrieval-Augmented Generation: A Comprehensive Survey of Architectures, Enhancements, and Robustness Frontiers**（2025）  
12. **A Survey on Knowledge-Oriented Retrieval-Augmented Generation**（2025）  
13. **Towards Multi-Source Retrieval-Augmented Generation via Synergizing Reasoning and Preference-Driven Retrieval**（2024）  
14. **Overview of the TREC 2025 Retrieval Augmented Generation (RAG) Track**（2026）  

### 这一组为什么适合论文
这一组最适合支撑论文中的：
- RAG 检索技术路线
- 多源/混合检索设计
- 深度检索中的检索—生成耦合
- 多源结果聚合与诊断分析

尤其是：
- **Self-RAG / Corrective RAG / Adaptive-RAG** 适合写“检索与生成如何动态配合”
- **RAPTOR / GraphRAG / HippoRAG / LightRAG** 适合写“检索组织方式和上下文构建”
- **Multi-Source RAG** 很适合“Web + RAG + ES”这条主线
- **RAGChecker / TREC RAG Track** 适合论文后面测试分析部分引用

## 二、深度检索流程、规划与推理方向

15. **ReAct: Synergizing Reasoning and Acting in Language Models**（2023）  
16. **Tree of Thoughts: Deliberate Problem Solving with Large Language Models**（2023）  
17. **Graph of Thoughts: Solving Elaborate Problems with Large Language Models**（2023）  
18. **Reflexion: Language Agents with Verbal Reinforcement Learning**（2023）  
19. **PlanGEN: A Multi-Agent Framework for Generating Planning and Reasoning Trajectories for Complex Problem Solving**（2025）  
20. **Understanding the Planning of LLM Agents: A Survey**（2024）  

### 这一组为什么适合论文
这一组文献适合支撑：
- 深度检索不是单轮问答，而是规划驱动的分阶段处理过程
- 先理解问题，再规划，再检索，再分析，再生成
- 研究计划和执行路径并非简单顺序回答，而是推理与行动结合

## 九、使用建议

建议后续不要全部只放 arXiv survey，最好搭配：

- **综述类**：用于写研究现状  
- **方法类**：用于写系统设计思路  
- **框架类**：用于写 Agent / 工作流  
- **评测类**：用于写测试和讨论  

这样参考文献结构会更自然，不会显得全是综述堆砌。
